# 4  系统设计

本章将对个人健康管理系统进行详细的系统设计，主要包括数据库设计和接口设计两部分。系统采用MySQL作为数据存储引擎，通过RESTful风格的API接口实现前后端数据交互。

## 4.1  数据库设计

### 4.1.1  E-R图设计

根据第3章的功能需求分析，本系统共涉及9张数据表。各实体之间的关系如图4-1所示，用户实体处于核心位置，与饮食记录、健康记录、健康模组、评论、食谱、流量指标等实体均存在一对多的关联关系；评论与评论点赞之间为一对多关系；健康模组与健康记录之间为一对多关系；食谱与饮食记录之间为一对多关系。

### 4.1.2  数据表结构

本系统数据库共包含9张数据表，以下分别对各表的结构进行说明。

**（1）用户表（user）**

用户表用于存储系统中所有用户的基本信息，包括管理员和普通用户两种角色。其结构如表4-1所示。

| avatar | TEXT | NULL | 用户头像URL |
| email | VARCHAR(50) | NULL | 用户邮箱 |

| birthday | DATE | NULL | 生日 |

**（2）健康资讯表（health_news）**

健康资讯表用于存储管理员发布的健康相关文章内容，支持富文本格式的正文存储。其结构如表4-2所示。

**（3）食谱表（recipe）**

食谱表用于存储用户创建的健康食谱信息，支持公开审核机制。其结构如表4-3所示。

**表4-3  食谱表结构**

| 字段名 | 数据类型 | 是否为空 | 说明 |

健康模组表是本系统的核心配置表之一，用于定义可监测的健康指标项及其属性。每个模组包含名称、单位、正常值范围等信息，支持全局共享和用户自定义两种模式。其结构如表4-4所示。

**表4-4  健康模组表结构**

| detail | VARCHAR(255) | NULL | 模组简介 |
| icon_url | VARCHAR(255) | NULL | 图标URL |
| unit | VARCHAR(30) | NULL | 单位（如：次/分钟、kg、mmHg） |
| symbol | VARCHAR(30) | NULL | 符号（如：HR、BMI、BP） |
| normal_value | VARCHAR(100) | NULL | 正常阈值范围（逗号分隔） |
| user_id | INT | NULL | 用户ID（外键，NULL表示全局模组） |
| is_global | TINYINT | NULL | 是否全局模组（0-否；1-是） |

**表4-9  流量指标表结构**

## 4.2  接口设计

本系统后端基于SpringBoot框架开发，采用RESTful风格设计API接口，前端通过HTTP请求与后端进行JSON格式的数据交互[1]。王以伍[1]指出："前端通过Ajax请求来访问后端的数据接口。"李俊[4]的研究表明："前后端分离架构通过A PI交互实现前端与后端的解耦。"系统共设计了11个控制器，涵盖60余个API端点，以下按功能模块列出核心接口。

### 4.2.1  用户认证接口

用户控制器（UserController）负责处理用户的注册、登录及个人信息管理，路径前缀为`/user`。主要接口如表4-10所示。

**表4-10  用户认证接口**

| HTTP方法 | 接口路径 | 功能说明 |
|----------|---------|---------|
| POST | /user/login | 用户登录，返回JWT令牌 |
| GET | /user/auth | Token校验，获取当前登录用户信息 |
| POST | /user/register | 新用户注册 |
| PUT | /user/update | 用户修改个人信息 |
| PUT | /user/updatePassword | 用户修改密码 |
| POST | /user/query | 分页查询用户列表（管理后台） |
| DELETE | /user/{id} | 按ID删除用户（管理后台） |

### 4.2.2  健康资讯接口

健康资讯控制器（HealthNewsController）负责资讯的发布、编辑、查询及推荐功能，路径前缀为`/health-news`。主要接口如表4-11所示。

**表4-11  健康资讯接口**

| HTTP方法 | 接口路径 | 功能说明 |
|----------|---------|---------|
| POST | /health-news/save | 新增资讯（管理员） |
| PUT | /health-news/update | 修改资讯（管理员） |
| DELETE | /health-news/{id} | 删除资讯（管理员） |
| GET | /health-news/{id} | 查询资讯详情 |
| POST | /health-news/list | 分页查询资讯列表 |
| GET | /health-news/recommend/{count} | 协同过滤推荐资讯 |
| POST | /health-news/collectionList | 查询当前用户收藏的资讯 |
| GET | /health-news/fetchHealthNewsTypes | 获取资讯分类枚举 |

### 4.2.3  食谱管理接口

食谱控制器（RecipeController）负责食谱的创建、审核、浏览及推荐功能，路径前缀为`/recipe`。主要接口如表4-12所示。

**表4-12  食谱管理接口**

| HTTP方法 | 接口路径 | 功能说明 |

## 4.3  本章小结

本章从数据库设计和接口设计两个维度对系统进行了详细的方案设计。在数据库方面，设计了包含9张数据表的MySQL数据库，通过E-R图明确了各实体间的关联关系，其中健康模组表和流量指标表的设计体现了本系统个性化健康管理和数据驱动推荐的特色；在接口设计方面，遵循RESTful规范设计了11个控制器共60余个API端点，实现了前后端的解耦与高效协作。下一章将在此基础上介绍各功能模块的具体实现。
